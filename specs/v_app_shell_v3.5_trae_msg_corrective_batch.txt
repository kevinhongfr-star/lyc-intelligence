### Fix 2: 3-Lane Detection (P0)

The engine must automatically detect which lane the user is in from their first message. **Never ask the user "which lane are you in."**

3 lanes:
- **Lane 1 — Leadership Advisory:** org strategy, team leadership, stakeholder management, board dynamics, culture
- **Lane 2 — Career Architecture:** career moves, positioning, transitions, personal brand, compensation, leveling
- **Lane 3 — Search Operations:** active search process, interview prep, offer negotiation, recruiter interactions

Lane detection rules:
- Infer from first message content + context
- Can shift mid-conversation if topic changes materially
- Lane state persists for the conversation
- User should never see "lane" as a UI concept — it's internal to the engine

Lane activates the corresponding variant in:
- Persona Constitution (lane-specific evidence base)
- Core Identity (lane-specific behavioral configuration)
- Pattern retrieval priority (lane-relevant patterns surface first)
- Voice calibration (subtle lane-specific temperature adjustments)
- Deep canon activation (lane-specific intellectual canon tier 3)

**China is the deepest evidence base, NOT the default frame.** Activated by Lane 3 detection + user context, not baked into the base persona.

### Fix 3: Lens Suggestion Logic (P1)

From v2.2 system prompt:
- 11 lenses total (CPI flagship + LEAP, COACH, PRISM, IMPACT, QUEST, BRIDGE, MOSAIC, DRIVE, SPARK, FORGE)
- Lenses are earned, not announced
- Signal threshold: 7/10 before a lens becomes suggestible
- Only suggest when conversation naturally opens to it
- If user says no, drop completely — no follow-up

Trust stages gate lens access:
- Introductory (0-1 sessions): only complimentary lenses (LEAP, PRISM)
- Working (2-4 sessions + 1 lens): all standard lenses
- Deep (5+ sessions + 3 lenses): signature lenses
- Partner (ongoing + ROI): team + enterprise

This logic must be implemented in the engine, not as UI chrome. The user never sees signal scores or trust stage numbers.

## NEXUS ENGINE — HOW TO INTEGRATE

The Python engine is in `nexus-engine/`. Key files:
- `nexus_llm_engine.py` — LLM client (DeepSeek API, reads DEEPSEEK_API_KEY from env)
- `nexus_engine.py` — Pattern retriever + scenario router
- `nexus_lens_memory_engine.py` — Lens scoring + memory
- `nexus_demo_server.py` — Reference HTTP server (see how it calls the engine)
- `nexus_llm_system_prompt_v2.2.txt` — MASTER SYSTEM PROMPT (use this as-is)
- `system_prompts/` — Individual layer files (reference only, v2.2 consolidates them)
- `pattern_db/patterns_v1.0.json` — Pattern DB (JSON for retrieval)
- `nexus_pattern_library_consolidated_v3.1.md` — 164 patterns (reference)

**Integration approach:**
Deploy as a Python Vercel Function that wraps the engine.
The Next.js app calls `/api/nexus-chat` → Python function → DeepSeek API → streams back.

Message persistence (Supabase conversations/messages) stays the same.
Only the response generation changes — from old Coze endpoint to NEXUS Engine with v2.2 prompt.

If Python Vercel Functions are problematic, wrap the engine in a simple HTTP service (see `nexus_demo_server.py` as reference) and deploy it separately. But prefer keeping it in the same repo as a server function.
