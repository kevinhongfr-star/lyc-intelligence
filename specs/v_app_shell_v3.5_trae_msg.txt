**This is NOT a static mock build. This is a FUNCTIONAL rebuild.**

- Your job: rebuild the UI shell to match the v3.5 mockups, while keeping all existing functionality intact.

## NON-NEGOTIABLE DESIGN RULES

1. **v3.5 design system ONLY** — ocean/teal/fuchsia palette, Crimson Pro display + Inter body + IBM Plex Mono meta
2. **ZERO border-radius** everywhere — no rounded corners, not even on buttons or cards
3. **No box shadows** — use 1px borders instead
4. **No gradients** — solid colors only
5. **Editorial minimalism** — rule lines, not cards; white space / iceberg principle
6. **App content column: 960px max-width, centered** — NOT 1160px like marketing
7. **Sidebar: 272px fixed width, ink-900 dark background**
8. **Topbar: 64px fixed height, white, bottom border 1px ink-100**
9. **Lens card pattern (APPROVED by Kevin):** code (top-left, mono, ocean-600) + score (top-right, Crimson Pro, big), lens name (Crimson Pro 16px/600), score bar (2px height), 1-line insight
10. **Active lens:** ocean-50 bg + 2px fuchsia top border
11. **Locked lens:** 0.45 opacity + dashed border + lock icon + "Upgrade to Executive to unlock"
12. **Second-person voice only** — "you", never "I/me/my"

## BACKEND INTEGRATION — PER VIEW

**Chat:**
- Wire to existing Supabase conversations + messages tables
- Use existing streaming chat endpoint (find it — could be /api/chat, edge function, or worker)
- Conversation list = real user conversations, sorted by recent
- Message thread = real messages for active conversation
- Composer = real streaming, not fake typing
- Preserve ALL existing agent orchestration, memory, context system, tools — only change the UI

**Lenses:**
- Use existing diagnostic/assessment system
- Scores = real computed scores from user's diagnostic data
- Tier gating = read from user's actual subscription tier
- Unlocked/locked computed from real tier, not hardcoded
- Insight text comes from real lens readout generation
- 11 lens definitions (code, name, suite, description) can be config — but everything dynamic must be real

**Milestones:**
- Use existing milestones/goals data model
- Status, progress, target dates = real data
- Click through to existing milestone detail if applicable

**Profile & Settings:**
- Profile from users table (name, email, company, role, tier, etc.)
- Settings = real preferences that persist on change
- Find existing settings schema and use it

**Documents:**
- Document list from real documents/reports table
- Status reflects real generation state
- Click = navigate to real document readout page

**Booking:**
- Session types mapped to real session products
- Calendar + time slots = real availability
- Confirm bar = creates real booking record
